# Power BI Dashboard — Technical Documentation

## Overview

The Power BI dashboard combines historical e-commerce performance analysis with a separate machine learning-based risk monitoring demonstration.
The report uses PostgreSQL analytical views imported into Power BI and consists of three pages: Executive Overview, Delivery Performance, and Risk Monitoring.

## Data Sources and Semantic Model

| Table | Granularity | Purpose |
|---|---|---|
| `Orders` | One row per order | Historical order, sales, and delivery metrics |
| `ShippingRoutes` | One row per order–seller pair | Shipping routes and geographical information |
| `CategorySales` | One row per order–product category | Product quantities and merchandise sales |
| `DimDate` | One row per calendar date | Historical date filtering and time-based analysis |
| `RiskMonitoring` | One row per scored synthetic order | ML risk scores, rankings, and delivery estimates |
| `CategoryDonut` | One row per category, plus Other | Dynamic Top 5 + Other category visualizations |
| `_Measures` | — | Centralized DAX measures |

### Relationships

The historical reporting model uses the following relationships:

- `DimDate[Date]` → `Orders[Purchase Date]` (1:*)
- `Orders[order_id]` → `ShippingRoutes[order_id]` (1:*)
- `Orders[order_id]` → `CategorySales[order_id]` (1:*)

All relationships use single-direction filtering.

`RiskMonitoring` remains disconnected from the historical model to prevent synthetic orders from affecting historical business metrics.

`CategoryDonut` is a disconnected helper table used by DAX measures to dynamically calculate the five leading categories and aggregate the remaining categories into Other.

### Data Refresh

The report uses Import mode.
Historical reporting data is refreshed from PostgreSQL analytical views. Risk Monitoring displays predictions previously generated by the Python scoring pipeline and stored in PostgreSQL.
Refreshing Power BI does not execute Python scripts or generate new predictions.

## KPI Definitions

### Executive Overview

| KPI | Definition |
|---|---|
| Total Orders | Number of orders in the selected period, regardless of order status |
| Delivered Orders | Number of orders with `delivered` status |
| Total Order Value | Total value of delivered orders, including product and freight charges |
| Average Order Value | Total Order Value divided by Delivered Orders |
| Category Items Sold | Number of product units sold in delivered orders |
| Category Sales Value | Merchandise value of delivered orders, excluding freight |

### Delivery Performance

| KPI | Definition |
|---|---|
| Average Delivery Days | Average actual delivery duration for assessable delivered orders |
| Late Deliveries | Number of assessable orders delivered after their estimated delivery date |
| Late Delivery Rate | Late Deliveries divided by the number of assessable delivered orders |

Delivery performance calculations exclude orders without sufficient information to determine delivery timeliness.

### Risk Monitoring

| KPI | Definition |
|---|---|
| Scored Orders | Number of synthetic orders evaluated by the ML model |
| High Risk Orders | Number of orders ranked in the highest-risk 10% |
| High Risk Share | Proportion of scored orders classified as High Risk |
| Scoring Model | Model version associated with the scoring results |
| Last Scoring | Timestamp of the latest scoring execution |

Risk scores are used for relative ranking and are not interpreted as calibrated probabilities of delivery delay.

## Filtering and Interactions

The **Executive Overview** and **Delivery Performance** pages use synchronized purchase-date and customer-state slicers.
Historical KPIs and visualizations respond to these filters through the shared `Orders` table and its relationships.
The product category donut charts dynamically recalculate their Top 5 categories and aggregate all remaining categories into **Other**. Each donut includes a count of categories represented by the Other segment.
The Delivery Performance map displays the absolute number of late deliveries by Brazilian state, while the accompanying state comparison chart shows late delivery rates.
The **Risk Monitoring** page uses an independent dataset. Historical slicers do not affect synthetic orders or their risk scores.

## Report Pages

| Page | Main Visualizations | Analytical Purpose |
|---|---|---|
| Executive Overview | KPI cards, monthly order and sales trends, product category donut charts | Monitor business performance and identify leading product categories |
| Delivery Performance | Delivery KPI cards, monthly delay trends, state-level comparisons, Azure Maps choropleth | Analyze delivery efficiency and geographical differences in delays |
| Risk Monitoring | Scoring KPI cards, risk score distribution, priority orders table | Demonstrate ML-based prioritization of synthetic orders |

## Key Design Decisions

**Product Category Analysis**

Two donut charts compare the top five categories by units sold and merchandise value. Remaining categories are aggregated into an Other segment using dynamic DAX measures. A separate card positioned inside each donut displays the number of categories included in Other.

**Geographical Analysis**

Azure Maps uses Brazilian state boundaries from a GeoJSON reference layer. The choropleth represents the absolute number of late deliveries, while the accompanying bar chart compares late delivery rates.
A fixed color scale ensures that state colors remain comparable when filters are applied.

**Risk Monitoring**

Synthetic orders are scored using a saved Logistic Regression pipeline. The priority orders table includes risk rankings, geographical information, delivery estimates, and model scores.
The page is designed for demonstrating relative risk prioritization rather than forecasting actual delivery outcomes.

## Report Usage

The dashboard is intended for exploratory business analysis and portfolio demonstration.
Historical performance metrics describe observed Olist transactions. Risk Monitoring illustrates a separate ML scoring workflow and should not be interpreted as a production-ready prediction system.
